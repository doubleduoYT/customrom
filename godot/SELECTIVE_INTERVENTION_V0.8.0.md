# Overuse Controller v0.8.0 — 선택형 개입 설계안

상태: **실험용 Android 알파**, 자동 CI 및 실기기 검증 전 정식 배포 금지.
기반: `feature/smart-recovery-v0.7.0` / Smart Recovery, 기존 Android-ARM64 + Windows x64 지원.

## 목표

기존의 '기기 전체 사용 시간에 따라 방해'에서, **사용자가 명시적으로 고른 오락 앱에 한해서만 단계가 올라가는 방식**으로 전환한다. 전화·설정·메시지·지도 등 필수 앱을 보호하고, 앱·권한 상태가 불확실하면 방해하지 않는다. 강제 차단이 아닌 터치 통과형 화면 효과를 유지한다.

## 첫 번째 구현 범위: Android 앱 선택형 (코드 추가됨)

- `선택한 Android 앱에서만 개입` 토글: **기본값 OFF**. OFF면 v0.7의 기존 전역 단계 정책을 유지.
- 사용자가 쉼표로 구분된 정확한 Android 패키지명을 직접 입력, `대상 앱 목록 저장`을 눌러 반영.
- 30개까지 허용하며 올바른 패키지 이름만 저장. 전체 앱 목록이나 실행 기록을 서버로 전송하지 않음.
- Android `UsageStatsManager.queryEvents`의 Activity resume/pause 신호로 전면 앱을 추정. 별도 **사용기록 접근 권한** 필요.
- 사용자가 직접 Android 설정에서 권한 허용해야 함. 권한 거부·철회, 알 수 없는 앱, 빈 대상 목록, 보호 앱에는 **오버레이와 루팅 CPU 제한 모두 미적용**.
- 앱 선택 모드에서 단계/누적 사용량은 **선택한 앱을 사용 중일 때만** 증가함.
- 선택하지 않은 앱으로 전환하거나 화면을 끄면 회복 진행. 단, '오늘 휴식 시간' 통계는 실제 화면이 꺼진 시간만 집계하고 다른 앱으로 전환한 시간은 휴식 통계에 포함하지 않음.
- 대상 목록/선택 모드를 바꾸면 **기존 단계와 회복 진행 상태 초기화**, 일일 통계는 보존(모드 변경 전후의 통계가 섞일 수 있음).
- 기존 15분 일시정지·중지 기능 유지. 선택형 모드의 회복 보너스는 v0.7 Smart Recovery 토글에 따름.
- 플러그인 클래스: `AppSelectionPolicy`(보호 목록, 순수 Java), `ForegroundAppMonitor`(사용기록 권한·이벤트 조회), `OveruseMonitorService`(정책 적용), `OveruseBridge`(Godot UI 연결).
- 고정 보호 앱에는 Android 설정, 시스템 UI, 통화, 문자, 일부 기본 런처와 지도 등이 포함. 기본 전화/SMS 앱은 가능한 경우 OS에서 동적으로 조회. **모든 제조사의 긴급 앱이 자동 식별된다는 보장은 없음**.

## 동작 규칙

| 상태 | 단계 증가 | 화면 오버레이 | 루팅 CPU 제한 |
| --- | --- | --- | --- |
| 선택형 모드 OFF | 기존 전역 규칙 | 기존 규칙 | 기존 동의 및 단계에 따름 |
| 모드 ON + 사용기록 권한 없음 | 정지 | 끔 | 복원 시도 |
| 모드 ON + 목록 비어 있음 | 증가 안 함 | 끔 | 복원 시도 |
| 모드 ON + 선택 앱 전면 | 증가 | 단계>0인 경우만 | 별도 활성화 시에만 |
| 모드 ON + 다른 앱 또는 보호 앱 | 회복 방향 | 끔 | 복원 시도 |
| 모드 ON + 전면 앱 불명 | 증가 안 함 | 끔 | 복원 시도 |
| 일시정지/중지 | 증가 안 함 | 끔 | 복원 시도 |

## 개인정보·사용자 통제

- 사용자 동의 없는 Accessibility Service, 화면 녹화, 콘텐츠 추출, 키 입력 감시 기능은 사용하지 않음.
- 사용기록 권한은 Android 설정에서 사용자가 직접 켜고 끄며, 선택형 모드 기능이 꺼진 경우에는 사용기록 접근을 시도하지 않음.
- 전면 앱의 패키지 이름은 메모리에서만 처리함. 저장하는 것은 사용자가 선택한 패키지 목록과 집계된 시간, 단계, 상태 코드뿐.
- 항상 알림에서 일시정지(15분) 및 종료 가능. 오버레이는 터치를 가로채지 않음.
- 권한이 없을 때는 '방해 효과를 끄는' 안전 우선 실패 정책을 적용. 고위험 시스템 설정, 전화, 지도 등에서 예외 동작을 실기기로 확인해야 함.

## 현재 한계/검증 필요

1. 패키지명 수동 입력 방식이라 일반 사용자에게 불편함. **설치된 앱 선택기**는 추후 버전에서 사용자 확인 및 최소 권한 원칙으로 구현.
2. `UsageEvents`는 OS·제조사·프로필 상태에 따라 누락되거나 늦게 전달될 수 있음. 특정 앱 전면 감지는 정확성을 보증하지 않으며, 불확실 시에는 방해하지 않음.
3. 기존 전체 화면 오버레이 및 루팅 CPU 제한은 앱 전환 후 다음 모니터링 주기(통상 약 2초)까지 남을 수 있어 실기기 점검이 필요함.
4. **Windows의 선택 앱 감지 및 선택 앱만 오버레이 적용은 아직 미구현**. Windows는 v0.7의 전역 방식 유지. 기존 Windows 선택 EXE CPU 제한은 별도 기능임.
5. 오늘의 누적 사용 시간이 모드 변경 전후에 섞일 수 있음. 통계 구분, 내보내기 및 효과 측정 설계를 후속 버전에서 개선.
6. Android 루트 CPUFreq는 기기 전체 클럭에 영향을 주므로 **항상 기본 OFF**. 시연은 루팅 없는 Android에서 화면 효과만으로 진행.
7. 선택형 모드의 효과가 실제 사용 시간을 줄이는지는 입증되지 않음. 빌드 성공은 실기기 검증이 아님.

## 시험 체크리스트

- Android 비루팅, 선택 모드 OFF에서 v0.7 동작이 변하지 않는지
- 선택 모드 ON, 사용기록 권한 미허용 → 어떤 앱에서도 오버레이 없음
- 목록 비어 있음, 선택 모드 ON → 언제나 오버레이 없음
- 테스트용 앱 패키지 1개를 선택 → 10분 후 단계 1, 2분마다 상승
- 선택 앱에서 보호 앱(전화·설정·문자·지도)으로 전환 → 최대 2초 이내에 방해 해제
- 선택 앱에서 다른 일반 앱으로 전환 → 단계 회복, 통계에서 비대상 앱 사용량 제외
- 홈 버튼/화면 잠금/배터리 최적화/알림 일시정지 및 종료 상황
- 실행 중 권한 철회 → 안전하게 오버레이 및 CPU 제한 해제
- Windows v0.7 회복/CPU 선택 제한 회귀 확인
