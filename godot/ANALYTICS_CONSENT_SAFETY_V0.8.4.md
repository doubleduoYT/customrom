# Overuse Controller v0.8.4-alpha — 통계 동의·삭제 안정성 개선

**실험판** · 기반: v0.8.3 opt-in usage analytics · 실기기 검증 전 병합/정식 배포 금지.

## 왜 수정하나

v0.8.3에서 대상 앱과 다른 앱 사용 시간은 별도의 '앱 통계 수집 동의'가 꺼져 있어도 자동으로 `today_target_ms` 및 `today_other_app_ms`에 저장되는 결함이 있었어. 또한 '사용 기록 삭제'는 패키지별 집계(`analytics_data`)만 삭제했기 때문에 이 두 누적 시간은 남았어.

v0.8.4는 **동의 없이 저장한 앱별 구분 집계가 남지 않도록** 고쳐.

## 구현

1. `AnalyticsConsentPolicy.canRecord()`: 선택형 모드 ON + 사용기록 접근 허용 + 화면 켜짐 + 현재 전면 앱 확인 가능 + 15분 일시정지 아님 + 앱 분석 동의 ON **전부 충족해야** 선택형 대상/다른 앱 시간을 기록.
2. `UsageAnalytics`의 패키지별 기록에도 같은 정책 적용. 동의 OFF에는 새로운 앱별 기록이 생성되지 않음.
3. **v0.8.3 이전 집계 이관 처리:** 앱 서비스가 v0.8.4에서 처음 실행될 때, 동의 없이 수집되었을 가능성이 있는 `today_target_ms` 및 `today_other_app_ms`를 한 번 삭제. 이미 사용자가 동의해 만든 과거의 앱별 집계도 이 두 요약값은 초기화되며, `analytics_data`는 유지.
4. **기록 삭제:** `analytics_data`, `today_target_ms`, `today_other_app_ms` 모두 삭제. 앱이 실행 중이면 네이티브 서비스 내부 집계까지 초기화해 재저장을 막음.
5. **기록 상태:** 동의 여부, 선택형 모드, 사용기록 권한, 보호 실행 상태 중 어떤 조건이 부족한지 UI에서 확인.
6. 기존의 `today_active_ms` / `today_rest_ms`는 원래 v0.7부터 존재한 *전체 단계 엔진*의 기본 사용·화면 OFF 카운터이므로, 앱별 통계 삭제와 무관하게 유지. 앱 UI의 확인창에서 해당 범위를 설명.
7. 기본값은 **앱 분석 OFF**, 블러 OFF, CPU 제한 OFF. 사용자의 데이터는 서버에 자동 전송되지 않고, 공유하기를 명시적으로 누를 때만 외부 앱으로 전달할 수 있음.

## 동의 상태 판정 표

| 분석 동의 | 선택형 | 사용기록 권한 | 화면 | 전면 앱 | 일시정지 | 앱별 시간 저장 |
|---|---|---|---|---|---|---|
| OFF | ON | 있음 | ON | 확인됨 | 아님 | **안 함** |
| ON | OFF | 있음 | ON | 확인됨 | 아님 | **안 함** |
| ON | ON | 없음 | ON | 확인됨 | 아님 | **안 함** |
| ON | ON | 있음 | OFF | 확인됨 | 아님 | **안 함** |
| ON | ON | 있음 | ON | 불명 | 아님 | **안 함** |
| ON | ON | 있음 | ON | 확인됨 | 일시정지 | **안 함** |
| ON | ON | 있음 | ON | 확인됨 | 아님 | **저장** |

## 자동 테스트

- 순수 Java `AnalyticsConsentPolicyTest`: 7개 핵심 허용/차단 시나리오
- 기존 `UsageAnalyticsTest`: opt-in, 앱 전환·재진입·데이터 초기화 등
- 기존 Android 플러그인 Gradle 컴파일, Godot 스모크/회복/선택 앱 체크 지속성 및 APK/Windows 빌드
- **CI 통과는 실제 Android 앱 전환 정확도나 화면 블러 동작을 증명하지 않음.**

## 실기기 QA (다음 단계)

1. 일반 Android 기기에서 Android 앱 사용기록 권한을 허용, 개입 대상 앱을 1개 지정해. 통계 토글은 **OFF** 상태로 시작.
2. 대상 앱과 다른 앱을 각각 약 1~2분 사용해. 앱별 시간은 0분이어야 하고 `UsageAnalytics` 앱별 목록도 비어 있어야 해.
3. 통계를 **ON**으로 설정하고 같은 시나리오를 반복해. 대상/다른 앱 합계가 분리되어 증가하는지 확인.
4. 다른 앱으로 이동 후 5분 이내 돌아와 **이탈 1회 + 재진입 1회**가 표시되는지 확인. 화면 잠금·홈 이동·비정상 중단은 자발적 이탈의 직접 증거로 취급하지 않아.
5. 기록 중 통계를 **OFF**로 전환하고 다시 앱을 사용해. 데이터가 *더 이상 늘지 않는지* 확인. OFF 이전 데이터는 삭제할 때까지 남을 수 있어.
6. 기록 삭제 확인을 누른 후, 앱별 통계와 대상/다른 앱 집계가 0이 되었는지 확인. 앱 종료·서비스 재시작 후에도 값이 되살아나지 않는지 확인.
7. Android 사용기록 권한을 철회하고 보호 앱(전화/설정/지도)으로 이동한 후, 화면 Blur/오버레이가 안전하게 사라지는지 확인.
8. Windows 빌드는 이전 v0.8.2 기능 그대로이며 실제 전체 화면 Blur는 여전히 미지원.

## 남은 한계

- 실제 앱 사용은 `UsageStatsManager`의 Activity 상태 이벤트 기반 추정이어서 제조사별로 지연/누락될 수 있어.
- 기존 전체 단계 엔진의 기본 사용·휴식 카운터는 앱별 분석 토글과 독립적으로 보존돼.
- 인과적인 스마트폰 사용 감소 효과는 사용자 동의하의 비교 실험이 필요해.
